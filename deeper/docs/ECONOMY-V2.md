## 0″. v2.21 現行工作模型（2026-07-28）——RTP-first sealed pool，分帶倍率演出

hao 指正：**RTP 分布分配的是 RTP，不是抽樣權重；operator 應先定目標 RTP，再分配各結果的 RTP 佔比。**
因此 v2.21 的控制面與結算面按以下順序拆分：

1. **RTP-first 調控**：tuner 開放 10 組匿名 row，每組只有「最小倍率、最大倍率、RTP 佔比、多久一次」；上下限相同代表固定倍率，不同則是均勻區間，不另設群組分類。`p = RTP contribution / mean multiplier`，多久一次＝`1/p`。
2. **目標先行、低倍補差**：先設定目標 RTP；增加任一列時，從倍率下限最低的列開始扣，不足才往上扣抵；降低時優先回補最低倍率列，不做平均或按比例分攤。所有正值列反推的 `Σp` 未用完部分自動成為 ×0；若 `Σp>1`，tuner 顯示局部錯誤並禁用執行。
3. **引擎仍吃概率表**：`CFG.poolExact`／`CFG.poolRange` 是由上述 RTP row 即時生成的執行格式，row 沒有 fish／beast tag。目標 RTP 同步縮放每筆 ANTE 的 EV，避免深度把 operator 設定拉回另一個 RTP。
4. **魚／泡泡是分帶獨立生成權重**：它們不讀 opening row；SHALLOWS／REEF／DEEPER／ABYSS 各自擁有倍率分布，預設平均倍率隨深度單調提高。自然路徑被鉤到後，顯示多少就支付多少；水池不足只能演成有清楚水隙的 miss。
5. **巨獸兩條表演路徑**：倍率保證路徑按 sealed pool budget 由 LIVYATAN→MOSASAUR→GREAT WHITE 判斷，三階各有門檻與機率，高階 miss 才落下一階；一旦命中便完整給獎且絕不斷鉤，並整組跳過 PULL 事件鏈。只有非強制巨獸表演局才走獨立 PULL 事件鏈；預算不足只切換斷鉤畫面，不改 payout／carry。
6. **ANTE、carry 與鯊魚契約**：ANTE 各買一個與目標同 EV 的 pool；普通鯊魚只按設定概率表演斷線，不讀水池正負。斷線時當局 pool 與 incoming safe-bank 全部 carry，故只延後交付、不銷毀價值。
7. **鯊魚 PRIZE 倍率區間可調**：沒咬斷的鯊魚轉成 WYSIWYG 獎品魚，使用 `CFG.sharkPrizeMin/max` 的 log-uniform 區間（預設 ×3–×10）。它重用 `makePrize` 原有第一支 value roll，不增加 RNG；設定只改本次可見交付組合，付不起仍自然錯過，sealed value 與長期 RTP 不被改寫。
8. **數量與倍率同區分帶設定**：`CFG.spawnDensity[band][family]` 管四帶 × 魚／泡泡／金魚的 0／1／2／3 每段數量；`CFG.appearanceByBand[band]` 管同一帶的魚／泡泡倍率。每個實體重用既有 tier roll，不增加 RNG；tuner 將兩者整合在同一深度區塊。
9. **PULL 巨獸事件鏈**：只有 PULL 封存後才知道是否真的鉤到金魚；有金魚使用 `goldFishTeaseP`，無金魚使用 `noGoldFishTeaseP`。預告成立後依序抽 `teaseToGreatWhiteP`、`greatWhiteToMosasaurP`。四項預設 0%，由 operator 保存後作用。

   保留已勾到的 base（＋滾存 bank，見 4），只失去更深的水池＋巨獸。
3. **巨獸＝倍率表三列**：WHALE/GREAT/MEGALODON 是 `POOL_TABLE` 三列，抽中率＝出現頻率；開局抽哪列鎖定

4. **★ 殘水滾存（CARRYOVER，safe-bank 模型）**：自願收網沒撈完的殘水（`poolBp − roundPay`）**滾成下一局的

   巨獸掙脫也不損 bank**——只有**當局**的殘水會被咬斷/掙脫沒收。⇒ **普通池變 play-independent**：你抽到的池子
   何時開獎都拿得到，只是分次拿。⚠ **巨獸列是 this-round-only（不滾存）**：巨獸的大池不併入 carry，否則會把
   「放棄的巨獸池」也保存下來、RTP 爆表（實測 L12 一度 108%）。遊戲端 `V.carryBp` 跨回合持久化。

## 0. 架構改制：物理即結果 → **水池制（結果先抽、物理負責演出來）**

**這是 v2 地基的更換，不是調參**（hao 2026-07-19 拍板）。

### 為什麼換掉「物理即結果」

確定性世界 ＋ 收網時機完全自由 ＝ **能模擬這局的對手永遠能挑到最好的瞬間**。實測：全知機器人
（掃描未來 12 個時機、逐一精算後挑最優）跑到 **265%**，而且怎麼縮放都關不掉——把它壓到 100% 以下
就會同時把真人玩法壓到 ~30%（hao 的體感「玩都輸錢」正是這個狀態的實測值：固定停損 L15 只有 33%、
潛到 L22 押出 3.38× 只拿回 0.17×）。**兩邊都不能出貨。**

⚠ 過程中另一個必須留痕的發現：`previewPull` 長期沒把 0.65s windup 算進去，等於歷來的 SHARP
都在優化過期資訊——**所有舊版凍結（97.5%／96.8%／95.4%／95.8%／95.5%）的「SHARP <100%」都比
實際寬鬆**。修正後才看見真實的 265%。舊版是寬走廊、對時機不敏感，差距應該小得多，但**未量化**。

### 新模型

**每次下注抽一支浮動倍率當作這一局的「水池」（預算）**，物理只負責把它演出來：預算夠就讓魚靠近鉤子，
預算用完就讓魚**剛好游過**（不是消失）。

| 倍率 | RTP 貢獻 | 機率 p=RTP/倍率 |
|---|---|---|
| ×0.5 | 20% | 40.00% |
| ×1 | 30% | 30.00% |
| ×2 | 16% | 8.00% |
| ×10 | 14% | 1.40% |
| ×30 | 12% | 0.40% |
| ×100 | 4% | 0.04% |
| **×0（全損）** | 0% | **20.16%**（＝1 − Σp，六列機率只加到 79.84%） |

**Σ RTP = 96.0%**（抽樣 200 萬次復現 96.00%）。命中率 79.84%，但**真正獲利（≥1×）只有 39.84%**——
×0.5 那列是「拿回一半」的體面輸法，near-miss 的情緒就住在那裡。

### 每一列都有它的演法（`world.js` 演出對映）

- **pool ≥ ×10 → 巨獸咬死**：×10/×30/×100 直接對映 WHALE／GREAT／MEGALODON。
  **大獎終於是一隻你看著牠出現的動物**，不是事後被告知的數字。
- **pool = ×0 → 其中 18.5% 演成巨獸掙脫**（最戲劇化的輸法），其餘是鯊魚咬斷或空手。
  「見鯨不等於得鯨」的 1:2 比例因此是從表裡自然長出來的，不是另外硬湊的。
- **其餘 → 普通釣魚局**。
- **巨獸只在你潛夠深（L≥12）才會出現**——擾動預告是誠實的邀請，讀水就是技巧。淺水收手＝
  你留下魚也永遠不知道錯過了什麼。

### 換來什麼（實測，非宣稱）

| | 舊（物理即結果） | 新（水池制） |
|---|---|---|
| 深度曲線 | **反的**（L3 52% → L30 0.4%） | **越深越多**（L3 2% → L20+ 95% 高原） |
| 反應時間影響 | 0.15s→79% ／ 0.45s→48% | **0.15s→82% ／ 0.28s→82% ／ 0.45s→82%（完全無關）** |
| 全知機器人 | 265%（無法收斂） | **56%——比真人玩法還低，時機無利可圖** |
| max win | ×66（×100 發不出去） | **×100 實測可達** |
| 下潛收費 | 每段抽（hao 抱怨「SINK 還會額外加注」） | **全面關閉**（房優已在表裡；roll 保留 p=0 以免動 rng 順序） |

### 代價（誠實記錄）

**GDD 的頂層支柱「物理即結果／所見即所得」語義改變**：玩家能算的不再是「我這一竿能撈到什麼」，
