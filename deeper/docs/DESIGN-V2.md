## 0. 設計主軸（hao 給的評分標準）

**「好玩的博弈 = 隨機性 × 大獎潛力 × 可計算性」**。這三者是本次每一個機制的驗收軸。
先講清楚三者在博弈設計裡的精確意義，避免做偏：

- **隨機性**：結果不可被玩家控制（房優固定、不可破）。
- **大獎潛力**：夢想可達且看得見——玩家能想像自己怎麼摸到 ×500。
- **可計算性**：**狀態透明 + 決策有意義**。玩家看得到魚、鯊、pot、mult，能對 EV 做有意義的判斷，
  產生「我在操盤」的能動感。⚠ 可計算 ≠ 可套利——邊際仍是不可破的 ~3%。
  P0 必須用 SHARP 策略證明「精明玩法天花板 <100%」，確保可計算沒有滑成可套利。

四個機制對三軸的映射（這就是為什麼它們是一套，不是四個點子）：

| 機制 | 隨機性 | 可計算性 | 大獎潛力 |
|---|---|---|---|
| 鉤子隨海流晃 + SINK 非垂直下放 | 晃動軌跡不可控 | 路徑看得見，可預判 | — |
| PULL 慢拉、只勾路徑上的魚 | 魚游動 → 誰落在路徑上 | 收之前能估哪些會中 | 抓準時機收滿一條路徑 |
| 魚留層遊動、上方潛力可見 | 游動位置 | 累積潛力總量可讀 | 多層潛力疊加的想像 |
| **分數魚 × 倍率魚** | 抽到什麼組合 | 即時 pot×mult 讀數 | **相乘爆獎（核心夢想）** |
| 鯊魚具象風險、擦線留層累積 | 撞線/擦過、鯊魚路徑 | 威脅數量看得見 | 對稱：越深風險越高、潛力也越高 |

## 1. 新核心循環

```
DROP → 鉤子入水，隨海流晃動下沉（非垂直，軌跡受 current 影響）
     → 每層 SINK：魚浮出、在該層遊動；鯊魚可能出現並游向線
        · 鯊魚「撞線」= SNAP（全失）  · 鯊魚「擦過」= MISS（近失，鯊魚留在該層 → 風險累積）
     → 任一 HOLD 點 PULL：線慢慢拉緊，鉤沿路徑上升，勾起「路徑上」的魚（不是全收）、撞爆路徑上的倍率泡泡
     → 賠付 = Σ(魚分 × 該魚吃到的泡泡倍數) → softcap → 夾頂（v2.1 修訂；cap=雙膝,已凍結 ECONOMY-V2 §1）
     → 每收 1 隻金色 scatter +30% 觸發 BEAST 事件 → 掙扎 2/3 掙脫全失／1/3 咬死爆 10–1000×（§8.5 三批版）
```

四個「每段都是真決策」的力（v2.1 起；原三力 + 概率收費回歸）：
0. **概率收費（v2.1，§8.4）**：REEF 起每段擲「是否收費」——下潛本身有隨機代價。
1. **鯊魚累積**：擦過的鯊魚留在層裡，越晚收、traverse 的鯊魚越多 → SNAP 機率越高（風險可見）。
2. **漂移風險**：魚在層裡越久漂得越開 → PULL 時越可能不在路徑上（看得到潛力 ≠ 收得到）。
3. **pot×mult 時機**：手上已有大 pot 或大 mult 時，「現在收 vs 賭下一層的組合」是真的兩難。

## 2. 經濟模型 v2（本次最大的變動）

### 2.1 兩種魚 + 相乘賠付

> **⚠ 2026-07-18 稍晚被 v2.1 修訂（§8.3）**：倍率載體「倍率魚」→「倍率泡泡」；乘法
> 「(Σscore)×(Σmult) 全 pot」→「**per-fish**（泡泡倍數乘勾著的其中一隻魚，可疊乘）」。
> 本節保留為決策脈絡——「Σ 比 Π 可讀、連乘爆點交給稀有大倍率」的論證仍是 per-fish 設計的
> 底層依據；**★ 浮動性原則不變**，直接沿用到泡泡值分佈。

- **分數魚（SCORE）**：帶基礎分值 `S_i`（點數）。是贏額的「量體」。
- **倍率魚（MULT）**：帶 `×M_j`。是贏額的「放大器」。
- **賠付 = softcap( (Σ 已收 S_i) × (Σ 已收 M_j，底 1) )，再夾 ×500**。

為什麼是 `Σscore × Σmult`（已定案）而不是 `Σscore × Πmult`：
- 兩個獨立量**相乘**，尾巴已經比 v1 的 `Σmult` 肥很多（大獎潛力達標）。
- Σmult（可加）比 Πmult（連乘）**可計算**得多——玩家心裡能算「20 分 × ×6 = 120」；連乘會爆掉可讀性、
  且 RTP 極難控。連乘的爆點改用**稀有大倍率魚（×50/×100）+ CURRENT 事件**提供，受 ×500 夾住。

**★ 浮動性原則（hao 定案，物理即結果的配套）**：因為結果由物理/表演驅動，經濟必須留容差才不被拉爆——
- 分數魚 `S_i`、倍率魚 `M_j` 的值是**分佈（範圍）而非定值**（如一條 mult 魚 = ×4–×8，由 seed/物理實現）。
- RTP 調成**穩健帶**而非精確點：~96–97% 要在物理驅動收魚的自然變異下成立。
- 「數學承受表演」= 值分佈 + 賠付公式設計成「物理怎麼跑，總體 RTP 都落帶內」。表演驅動、數學容納。
- ⚠ 但「只減不增期望」仍是鐵則：浮動性給的是**變異**（手感），不是**正期望漏洞**（見 §0 SHARP <100% 驗證）。

**核心夢想的具象**：玩家看著手上 pot 累到 60 分，這時上方漂著一條 ×8 mult——「再賭一層把它勾到，
就是 ×480」。這個「差臨門一腳」的張力就是 §0 的大獎潛力 + 可計算性同時發生的瞬間。

### 2.2 空間收魚模型（取代 CATCH_P 機率骰）

v1 是「每魚 38% 上鉤」的純機率。v2 改成**空間**：
- 每條魚在層裡有一個「離 PULL 路徑的偏移」，偏移分佈的**擴散度隨魚在層裡停留時間 + 深度增大**。
- PULL 時：偏移 < `catch_radius` 的魚被勾起，其餘逃走。
- **headless sim 可模型化**：不需真動畫——把「每魚上鉤率」表達成「該層擴散度 vs catch_radius」的
  幾何函數即可。深層 = 擴散大 = 上鉤率低 = 你看得到潛力但收不滿（隨機性 + 可計算性）。
- 調參旋鈕：`catch_radius`、每層 `drift_spread`（取代 CATCH_P）。

### 2.3 鯊魚風險模型（取代 snapP(L)）

- 鯊魚按層機率生成、游向線；接觸時擲：**HIT（p_hit → SNAP）** 或 **GRAZE（→ MISS，留在層裡）**。
- 已 traverse 層 + 當前層的鯊魚數累加成 hazard；每次下潛 roll 對抗總 hazard。
- 取代 `snapP(L)`：snap 機率變成**鯊魚數的函數**（路徑相依、可見），但仍由 seeded RNG 決定、可調、
  可重現。深 = 累積鯊魚多 = 風險高，保住 v1 的風險爬坡，但變成看得見、可推理的。
- 調參旋鈕：鯊魚生成率、`p_hit`、hazard 累積曲線。
- **對稱性（hao 的要求）**：魚（機會）和鯊（風險）都是層裡累積的空間實體，越深兩者都疊高。

## 3. 決定性與 provably-fair（已定案：B 物理即結果）

一旦魚的位置、鯊魚、鉤的路徑會**決定賠付**，這些運動就不能再用 `Math.random()`（v1 它們是純裝飾）。

**決策 = B 物理即結果**，配 hao 的關鍵原則「倍率浮動、數學承受表演」（§2.1）。

意義：seeded 的**確定性物理引擎**（固定時間步 fixed-timestep）驅動海流、鉤晃動/非垂直下沉、魚游動、
鯊魚 AI——全部可重現。賠付從**真實物理**湧現：你收到的 = PULL 當下真的落在 catch_radius 內的魚。
這是最誠實、可計算性最強的路——**你看到的就是決定結果的**（B 的可計算性 > A 的編排貼合）。
代價是 RTP 只能靠調物理參數 + 海量 headless sim 間接控，用 §2.1 的浮動性/穩健帶吸收。

**Provably-fair**：結果 = f(seed, pull_times)，PULL 時機是玩家真輸入。server 用同一 seed +
玩家記錄的 PULL 時機，重跑同一份確定性引擎驗證。

**⚠ 已知硬挑戰（誠實記錄，勿當已解）**：**跨平台浮點確定性**——不同 CPU/瀏覽器的 float 物理可能發散。
解法路徑：固定時間步 + 確定性運算；真金階段用**定點運算（fixed-point）或 verify-by-replay**。
prototype/demo 先接受「同引擎確定性」，跨平台硬化延到真金後端（P6）。這是採 B 的最大長期成本。

**架構後果（v1 的自然演進，也是本次的骨架）**：
- v1 讓「**econ**」在遊戲與 sim 間共用同一份 code；**v2 讓整個「確定性物理核心」共用**。
- render 只是這個核心的一個 **view**（回放 + 插值），不產生任何影響賠付的亂數。
- 所有「影響賠付」的運動搬進 seeded stream（魚生成/游動、鯊魚路徑、海流晃動）；只有純裝飾
  （grain、遠景 ambiance）留 `Math.random()`。
- sim harness 跑**同一份物理引擎**（headless、不繪製）算 RTP，PULL 時機用行為策略（沿用 v1 harness）。
- **diff-play gate 升級**：headless 與 live 對同 seed + 同 PULL 時機**逐位元一致**。

### 8.1 世界觀場景：巨船、海面、重鉤（P2v2）
> ↳ **2026-07-19 hao 拍板:船體整個移除**（本節「巨大船體/待機即入水的絞盤敘事」中,船的具象已廢

- **巨大船體**：水面上只見**仰視的船底/船體**——不塞滿版寬、左右仍見天空；玩家視角=水中仰望，
