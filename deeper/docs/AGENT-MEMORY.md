# DEEPER — Shared Agent Memory

> Claude Code 與 Codex 的 repo-local 共用長期記憶。最後整理：2026-07-23。
>
> 優先序：使用者當下指示 → `AGENTS.md`（`CLAUDE.md` 同一檔）→ 專門真相源文件 → 本檔
> → 工具私有 auto-memory。私有 memory 只能當搜尋線索，不能覆蓋 repo 的現況。

## 每次任務的同步契約

1. 開始前先讀本檔，再依 `AGENTS.md` 的 docs 路由讀與任務相關的真相源；不要靠聊天或私有 memory 猜現況。
2. 長期有效的新知必須在同一批次寫回 repo：
   - 安全鐵則、架構入口、固定命令 → `AGENTS.md`
   - 遊戲設計／經濟／視覺／巨獸／部署 → 對應 `docs/*.md`
   - 跨領域偏好、反覆踩坑、協作方法 → 本檔
3. 改到遊戲行為或設計事實時，同批更新 `docs/GDD.md` 與對應開發文件，完成前做端到端驗證；純機械重構可免。
4. 不在本檔複製會快速過期的版本號、RTP、線上部署狀態或長篇實作史；只留指向，避免第二真相源。
5. 若工具私有 memory 與 repo 衝突，以 repo 為準，並把仍有效的獨有知識遷回 repo；不要反向把舊摘要覆蓋進文件。

## 已遷移的耐久偏好與工作紀律

- 博彩數值先於美術：涉及 `world.js`／`entities.js` 經濟常數時，依根設定重開 sim gate；美術／手感批次不得暗帶數值變更。
- 「完成」必須有與風險相稱的實際端到端驗證，不能只靠讀 code 或 build 成功宣告。
- 視覺不要像系統功能或通用 AI 模板；材質與配色以 `docs/design-system.md` 為準。若同一 UI 會出現在深／淺背景，需同時驗證兩種對比狀態。
- 巨獸要兇、恐怖、不可愛，且動勢必須來自姿態與運動模型，不是靜態圖平移。完整正反例以 `docs/BEAST-VISUAL.md`、`docs/DEV-LOG-V2.md` 為準。
- 新增巨獸姿態時先以現有素材做造型參考；使用已包含在 Codex／ChatGPT 額度內的生圖可直接進行，另行付費的影像 API 才先詢問。
- 使用者以文件作為迭代對照面；行為落地與文件更新必須同批完成，不累積到事後補寫。
- DEEPER 的「進水／表演脫鉤」只代表魚與泡泡的**生成權重不受進水倍率控制**；不是顯示值與賠付值脫鉤。魚身與泡泡只有一份經濟真值，水池不足時必須用路徑外 miss 表達，禁止 hidden carrier、softcap 或「看到 100 實付 30」。
- RTP 分布與表演選角也必須完全脫鉤：RTP 控制台先設定**目標 RTP**，再以最多 10 組匿名結果直接分配 RTP 佔比；每組直接編輯**最小倍率／最大倍率**（相同＝固定、不同＝區間），不使用中心倍率＋±浮動，也不設「群組」分類。命中概率與多久一次由 `該列 RTP ÷ 區間平均倍率` 反推，剩餘概率自動成為 ×0。巨獸分兩條：①倍率保證階層按 sealed pool budget 從 LIVYATAN→MOSASAUR→GREAT WHITE 高到低判定，抽中必給獎且絕不斷鉤；該路徑在 PULL 另加一隻零經濟的表演金魚，優先放在較深隨機路徑並從鏡頭外自然進場，鉤中後才啟動巨獸，禁止原地突現，也不得回填實際金魚／事件統計；②沒抽中才走 PULL 表演鏈，依本次是否真的鉤到金魚選預告率，再抽預告→GREAT WHITE→MOSASAUR，預算不足只改成斷鉤表演，不得改寫已封存錢。
- 巨獸統計的預告漏斗必須跨倍率保證與 PULL 事件兩條路徑：預告=`whaleTease`（含落空）、真咬=`whaleTriggered`、升蒼龍=`beastTier>=1`。不可只統計 `pullBeastTeased`，否則會漏掉全部強制巨獸預告，造成「預告頻率低於大白鯊」的反直覺結果。
- RTP 佔比的自動補差必須是**低倍優先**而非平均／按比例分攤：某列增加時，按倍率下限由低到高逐列扣抵，最低列不夠才扣下一列；某列降低或目標 RTP 增加時，釋出量優先回補最低倍率列。補差精度固定 0.001pp，空白備用列不可只因四捨五入尾數被意外啟用。
- 鯊魚沒咬斷時轉成的 PRIZE 魚必須使用可設定的倍率區間；預設 ×3–×10，畫面顯示值就是實付值。區間抽樣重用 `makePrize` 既有第一支 value roll，不得為調參新增 RNG 消耗。
- 普通水中鯊魚的咬斷表演不得讀水池正負：每段只按 `sharkSpawnP × sharkBiteP` 判定。咬斷會中止當局交付，但 `ordinaryPoolBp + carryInBp` 必須完整進 `carryOutBp`，所以只延後支付、不銷毀正值水池；控制台以百分比編輯兩項概率。
- 深度演出一律在同一個四帶控制面設定：SHALLOWS／REEF／DEEPER／ABYSS 各自擁有魚／泡泡／金魚每段 0／1／2／3 個的數量權重，以及魚／泡泡的倍率權重；預設平均倍率必須隨深度單調提高。調一列只可自動補完該帶該分布到 100%，禁止用全局 min/max 或 scale 偷套全部深度。內部 `SCATTER/scatter` 名稱為相容識別，不是玩家文案；UI 一律稱「金魚」。金魚預告只在 PULL 封存「實際有鉤到金魚」後才抽；沒鉤到則走獨立無金魚預告率，兩者都必須允許落空。
- 權重控制每個分布只使用**一條高對比堆疊 BAR**：每個色塊寬度就是實際比例，點色塊／名稱後可分別拖左界與右界；拖右界只能重分配右側，左側權重必須 bit-for-bit 保持，拖左界反之。禁止每項各排一支 slider、chips 再外掛另一條 slider，或堆大量 number input。0% 項目仍須能從名稱選回，總和即時保持 100%。
- tuner 的 operator 保存值高於程式預設：只有使用者親自按「保存參數」才可寫入真實調控層；Claude Code／Codex 不得主動點保存、寫入、重置或替使用者改保存參數，只能修改 repo 內的預設值與介面。載入時保存值逐欄優先，程式預設只補缺少／新增欄位；跑模擬不等於保存，還原預設也必須保持未保存直到使用者確認。
- operator 保存成功後必須立即同步到同源遊戲環境：IDLE 可立即套用；活躍回合只接收並排隊到下一局起手前，禁止半局更換經濟設定。遊戲重新載入也必須讀最後保存值；tuner 未保存草稿永遠不得流入遊戲。
- tuner 有草稿改動時底部必須浮出「恢復／保存」；恢復回最後保存（未保存過則回預設）但不寫保存層。尚未跑出與目前參數匹配的真模擬時，結果區以 skeleton 屏蔽數字，僅保留 KPI／圖表／頻率表輪廓；不得顯示過期或假結果。
- tuner header 的模擬操作只用一顆原位換狀態按鈕：閒置「跑模擬」、執行時立即變成「模擬中…%」並 disabled，完成後恢復；不要在旁邊再顯示第二個可見的模擬狀態，詳細進度仍由既有頂部 progress bar 承接。
- tuner header 的「最後設定時間」固定置中放在跑模擬按鈕正下方，兩者共用穩定寬度的垂直群組；不要把時間另排在按鈕左側造成 header 資訊散開。
- tuner 的桌面寬版禁止「結果左／設定右」兩條不等長長欄，否則捲到深度參數時會留下大片空白。結果摘要放上方自適應網格，設定區在下方吃滿整列；寬螢幕事件群組與四個深度帶可各自雙欄，窄版依 DOM 順序退回單欄。結果表太寬時只讓表本身水平捲動，禁止整頁出現橫向捲軸。
- tuner 資訊架構必須把「倍率數學」「表演事件」「四階深度」明確分群：加注屬倍率模型；保證巨獸／PULL 巨獸／SINK 鯊魚屬表演；每階數量與魚／泡泡倍率屬深度演出。四階不能只用顏色區分，需同時顯示 01–04、英文名、中文層級與深度／段數，並提供可鍵盤操作的快速定位。
- 手機 Web 禁止用 `user-scalable=no`／`maximum-scale=1` 一刀切掉輔助縮放；要避免雙擊放大與 tap delay，優先對遊戲手勢面／按鈕／熱區使用 `touch-action:none` 或 `manipulation`。tuner 的手機 number／select 字級至少 16px、主要點擊熱區至少 44px，避免 iOS 聚焦自動放大。
- PULL 的命中必須是「自然路徑先成立、結果再從路徑內選」：SINK 中魚／泡泡維持隨機出生點與自由游線，禁止預靠線、PULL 瞬間補位或在收網開始時把未採用物件整批推開；也禁止 bottom→top 花預算造成上方物件集體逃跑。只有未修改軌跡真的會接觸但付不起的魚／泡泡，才可在鉤逼近時做局部 near-miss。PULL 時機可改變 paid-now，但 `paid-now + safe carry` 必須不變。
- PULL 接觸只有一個時鐘：判定與 live reel 必須共用實際起拉深度、`PULL_WINDUP` 與 `REEL_SPEED`。禁止畫面另做實體鉤變速／停頓而讓魚繼續游；節奏只能放在 shake、flash、audio 等不改接觸時間的 FX，否則會重現「畫面碰到但引擎先前判 miss」。
- 魚的運動偏好是「長時間朝一個方向順游、偶爾平滑轉向、每隻有 seed 個體速度」，禁止用多組高頻諧波堆出忽快忽慢或用朝向符號瞬間鏡像。PULL 接觸以**可見輪廓**而非中心點為真相：看起來碰到就必須 catch/pop；付不起的物件要在鉤到達前留下清楚水隙，不能穿模或碰到卻不結算。
- 泡泡的接觸半徑必須以 `BUBBLE_BODY_RADIUS × perspectiveScale` 的完整可見圓為底，再加鉤身可見 reach；不可像舊版再縮成 72%。經濟 `b.popped` 與表演 `_popped` 必須分開：前者在 PULL 封存，後者只能在鉤子實際經過的 frame 切換，爆點使用投影座標。
- 魚／泡泡／失手鯊魚 PRIZE 的 catch geometry 一律是「完整投影可見輪廓＋14px 鉤身 reach」，不可再用縮小 body 百分比。攻擊中的鯊魚只在碰線 frame 揭曉 hazard；miss 必須在 reel windup 結束前轉成帶真實分值且仍具鯊魚輪廓的 PRIZE，之後直接走普通魚 catch path，禁止同畫面存在不可勾 shark lane。
